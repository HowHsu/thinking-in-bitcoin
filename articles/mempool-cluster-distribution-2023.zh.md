# 2023 年全年 Mempool 实测：Cluster 大小与拓扑分布

[English](mempool-cluster-distribution-2023.en.md)

---

## 动机

Cluster mempool 将 mempool 中的交易按依赖关系分组为 cluster。每个 cluster 的**大小**
（交易数量）和**拓扑**（是否为严格链式）直接影响线性化算法的行为和代价。

本文基于 [Pieter Wuille](https://github.com/sipa) 发布的 2023 全年 mempool 快照数据，
统计 cluster 的大小分布和链式拓扑占比，描绘真实 mempool 的结构特征。

---

## 数据来源

数据来自 [bitcoin.sipa.be/mempool_dumps/sim2023/](https://bitcoin.sipa.be/mempool_dumps/sim2023/)，
包含 2023-01-01 至 2024-01-01 共 366 个每日压缩文件（`txgraph.YYYYMMDD.xz`）。

每个文件为二进制格式，由若干次 mempool 快照（dump）组成：

```
[uint64_t timestamp (8 字节, LE)]
[DepGraphFormatter 编码的 cluster 序列]
[0x00  空 cluster，标记本次快照结束]
... 重复至 EOF
```

**链式 cluster 的定义**：N 笔交易构成一条严格的线性依赖链 tx₀→tx₁→…→tx_{N−1}，
等价于按拓扑序排列后第 i 个交易恰好有 i 个祖先。

解析工具：[`scripts/parse_mempool_xz.py`](../scripts/parse_mempool_xz.py) 和
[`scripts/cluster_parser.c`](../scripts/cluster_parser.c)（C 扩展，约 340× 快于纯 Python）。

## 关键发现

### 1. Size 1–2：始终是链式

- **Size 1**（单笔交易）：无依赖关系，满足链式定义。
- **Size 2**：同一 cluster 中的两笔交易必然有一条依赖边（否则会分属不同 cluster），
  两节点单边 DAG 就是一条链。

### 2. Size 3–25：链式比例随大小递减

从 3-tx cluster（70% 链式）到 25-tx cluster（3.6%），链式比例单调下降。
cluster 越大，越可能包含多父交易（如 consolidation：一笔交易消费多个未确认父交易
的输出）或分叉结构（一笔父交易有多个未确认子交易），破坏严格的线性链拓扑。

仅看 size ≥ 3 的 cluster，链式比例为 **22.8%**。
仅看 size ≥ 5 的 cluster，链式比例进一步降至 **9.4%**。

### 3. Size 25 的数量异常

25-tx cluster 出现了 **1.7 亿次**，是 24-tx（3320 万次）的 **5 倍**。

这直接源于 Bitcoin Core 默认的 **mempool 祖先/后裔限制（25 笔）**：任何一笔交易
在 mempool 中的祖先链（含自身）最长为 25 笔。25-tx cluster 是 CPFP 链在此限制下
能达到的最大规模，它们往往在 mempool 中长时间驻留（等待被挖出），因此在快照计数
中累积出不成比例的高出现次数。

其中仅 3.6% 为严格链式——大多数 25-tx cluster 含有分叉或合并结构，尤其在 2023 年
Ordinals/BRC-20 盛行期间。

### 4. Size 26：硬断崖

26-tx cluster 出现 5,998 万次，但**链式仅 3 个**（chain% ≈ 0%）。

原因：一条 26 笔的严格线性链中，第 26 笔交易有 25 个祖先——刚好触及 mempool 策略
上限。标准的 Bitcoin Core 节点会拒绝这样的交易入池。因此 26-tx cluster 内部必然
存在**分叉结构**，让部分交易共享祖先名额而不超限。

### 5. Size 27+：链式 cluster 完全消失

27 笔及以上的 cluster（约 490 万次出现）全部为非链式，原因与 size 26 相同。
在默认 mempool 策略下，不可能存在 27+ 笔的线性链。

## 月度趋势

| 月份 | Cluster 出现次数 | Chain% |
|------|:---:|:---:|
| 2023-01 | 158M | 99.02% |
| 2023-02 | 374M | 99.31% |
| 2023-03 | 732M | 99.46% |
| 2023-04 | 702M | 94.85% |
| 2023-05 | 1,865M | 93.46% |
| 2023-06 | 2,763M | 97.07% |
| 2023-07 | 3,926M | 98.25% |
| 2023-08 | 6,394M | 99.42% |
| 2023-09 | 4,574M | 99.31% |
| 2023-10 | 368M | 96.75% |
| 2023-11 | 3,056M | 97.61% |
| 2023-12 | 2,679M | 95.88% |

以上 chain% 受 size=1 主导（占 93%），各月数值高度接近。
更有意义的是观察**月度 cluster 总量**的变化：

- **2023 年 1–3 月**：mempool 相对平静，日均约 500 万个 cluster 出现。
- **2023 年 4–5 月**：**BRC-20 代币**爆发，mempool 严重拥塞，月度 cluster 数量从
  7 亿暴涨至 18.6 亿——非链式 cluster（inscription 交易的复杂依赖结构）大量涌入，
  chain% 从 99% 降至 93%。
- **2023 年 8 月**：cluster 数量达全年峰值（64 亿次），但 chain% 回升至 99.4%。
  这表明此时大量交易以孤立方式进入 mempool（每笔各自成一个 size=1 cluster），
  而非形成复杂的相互依赖。
- **2023 年 10 月**：mempool 骤然缩小（3.7 亿次，接近年初水平），但 chain%
  仅 96.7%——说明虽然交易量少，但留下来的 cluster 中有更高比例的非链式结构。
- **2023 年 11–12 月**：第二波拥塞（Ordinals 持续 + Runes 预热），cluster 数量
  回升至 26–30 亿，chain% 在 96–98% 之间。

## 总结

| 观察 | 数据 |
|------|------|
| mempool 中最常见的 cluster 类型 | 单笔交易（93%） |
| size ≥ 3 cluster 中链式占比 | 22.8% |
| size ≥ 5 cluster 中链式占比 | 9.4% |
| 链式 cluster 的最大长度（受 mempool 策略限制） | 25 |
| 非链式 cluster 数量与 BRC-20/Ordinals 拥塞的相关性 | 高 |

**核心结论**：在任意时刻的 mempool 快照中，绝大多数 cluster 是只含 1–2 笔交易的
简单结构。多交易 cluster（size ≥ 3）仅占 2.7%，且其中大部分不是严格链式的——
尤其在 2023 年 inscription 拥塞期间，非链式大 cluster 显著增多。链式 cluster 在
size 26 处出现硬断崖（由 25 笔祖先限制导致），27+ 笔的链式 cluster 不存在。

## 复现

解析脚本和 C 扩展位于 `scripts/` 目录：

```bash
# 编译 C 扩展
gcc -O3 -march=native -shared -fPIC \
    -o scripts/cluster_parser.so scripts/cluster_parser.c

# 运行（--workers N 控制并行数）
python3 scripts/parse_mempool_xz.py /path/to/2023_mempool/ --workers 7
```

文件下载：

```bash
# 生成 URL 列表
python3 -c "
from datetime import date, timedelta
d, end = date(2023,1,1), date(2024,1,2)
while d < end:
    print(f'https://bitcoin.sipa.be/mempool_dumps/sim2023/txgraph.{d:%Y%m%d}.xz')
    d += timedelta(days=1)
" > /tmp/mempool_urls.txt

# 并行下载
cat /tmp/mempool_urls.txt | xargs -P8 -I{} wget -q -P /path/to/2023_mempool/ {}
```
