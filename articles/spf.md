# Cluster线性化：生成森林算法（Spanning-forest）

对Cluster进行线性化排序由多种算法，目前(2025/01/16)的Bitcoin Core使用的是SPF算法。这是一种由单纯形法改进而来的算法。

## 1. 背景：cluster线性化抽象成线性规划问题
Cluster的线性化（找到费率图最优的Cluster线性化序列）可以通过不断寻找‘最高费率的拓扑有效子集’，然后从Cluster中删除这个子集并对剩余交易集合继续这个过程来实现。因此，Cluster的线性化问题等价于找到最高费率拓扑有效子集。这个问题可以被抽象成一个线性规划问题。
- 对每个交易$i$, 设置一个变量$t_i \in \mathbb{R}_{\ge 0}$。$t_i$ > 0 表示把交易i加入结果集合中。$t_i$ = 0 表示不包含它。这里用实数类型而不是boolen类型看起来有点奇怪，但是后面可以看到所有的非零$t_i$，它们一定相等。
- 对于Cluster中的边（parent-child pair (p, c)），设置不等式$t_p >= t_c$。这样就表达了如果结果包含了孩子，则一定包含父亲。
- 那么目标函数就是$g = \sum_i t_i \mathrm{fee}(i) \,/\, \sum_i t_i \mathrm{size}(i)$ ， 也就是结果集合的费率。
- 为了使目标函数呈线性（线性规划的要求），我们增加一个规范化约束：$\sum_i t_i \mathrm{size}(i) = 1$ 。这样目标函数变成：$g = \sum_i t_i \mathrm{fee}(i)$。
可以这样做的原因是分子分母是“齐式的”，也就是分子分母同时除以一个数不会导致结果改变，亦即g(vt) = g(t)，当我们求得原目标函数的最大值时，总能找到一个合适的v，使得分母为1。因此其等价于寻找$\sum_i t_i \mathrm{size}(i) = 1$约束下的$g = \sum_i t_i \mathrm{fee}(i)$。

到此，我们可以有两个推论：
- Cluster的线性化问题可以借助多项式时间的线性规划算法在多项式时间内解决，如内点法。这些不是这个问题的最好解法，但是它们设定了一个上界，证明这个问题不是NP-hard问题。
- 线性规划问题解决方案的研究和技术可以应用到我们的问题中。

### 1.1. 寻找最高费率集合的单纯形算法
解决线性规划问题最广为人知和使用最广泛的算法是单纯形法。
单纯形法要求问题和优化目标被表达为一系列非负实数变量的等式。我们的问题中，$t_i$已经是非负的了，但是我们还有一些不等式没处理。我们可以引入一些辅助变量来把不等式转换成等式：
- 引入 $d_j \in \mathbb{R}_{\ge 0}, d_j = t_{p_j} - t_{c_j}$，其中 $(p_j, c_j)$ 是一条有向边。

我们现在有n个交易和m个依赖（边），这意味着n+m+1个变量（$t_{1...n}, d_{1...m}, g)$和m+2个约束：
- $t_{p_j}-t_{c_j} - d_j = 0$ (j = 1...m)
- $g = \sum_i t_i \mathrm{fee}(i)$ (目标函数)
- $\sum_i t_i \mathrm{size}(i) = 1$ （正规化）

单纯形法维护n-1个自由变量，这些自由变量等于0。所有其他变量（基变量）可以由自由变量和m+2个等式计算得到$^1$。算法的每一步是选出上一步中的一个自由变量改为基变量，一个基变量改为自由变量。在Cluster线性化这个问题的上下文中等价于：
- 一个自由的$t_i$表示交易$i$被排除出结果集合
- 一个自由的$d_j$表示交易$p_j$和$c_j$要么都被包括进结果，要么都被排除出结果结合。

我们可以应用一些规则来选择自由/基变量，使得每步至少不倒退并且保持结果合法（拓扑有序）。此外，存在着多种策略来尝试最大化每步的优化。

### 1.2. 把单纯形法的步骤映射到我们的问题上

注意一点，一些交易通过一些自由变量$d_j$连接在一起，因此它们必须全部被包含在结果中或者全部不被包含在结果中。我们把这样的交易集称作块（chunk）$^2$。
由于单纯形法的一些规则，我们可以进一步得到：
- chunk中没有环（注意：chunk中的边是自由的$d_j$），否则必有一个$d_j = 0$是多余的。$^3$
- chunk中最多有一个自由的$t_i$，即$t_i = 0$
- 因为有$n - 1$个自由变量，所以除了一个chunk包含一个基变量$t_i$，其余每个chunk各自包含一个自由的$t_i$。$^4$

总的来说，这意味着单纯形法的单步状态对应着交易图被划分为若干chunk，每个chunk在数据结构上是一个生成树，其边是自由$d_j$，其中有且仅有一个chunk是结果集。单纯形法的每一步需要将一个自由变量变成基变量，将一个基变量变成自由变量，从几何意义上这是从一个单纯形的一个顶点移动到另一个顶点，并且必须满足这种移动使得答案更优（至少不能变差）。那么代入Cluster线性化的上下文， 是什么含义呢：
- 自由变量 --> 基变量
    - $t_i$：一个被排除的费率优于现有结果的chunk被设定为非排除。它有可能变成包含，也有可能后续被其它chunk（包含或非包含$^5$）合并，下面会详述。①
    - $d_j$：一个chunk分割成两个chunk，前提是top chunk（包含$d_j$的parent交易）的费率高于当前结果集或者bottom chunk（包含$d_j$的child交易）的费率低于当前结果集。②
- 基变量 --> 自由变量
    - $t_i$：上一步中的包含chunk（即结果集）被设为排除。前提是这步中对应的操作（即自由变量 --> 基变量）涉及的chunk（①或②）不依赖任何其他chunk。$^6$
    - $d_j$：①或②中的chunk和另一个chunk合并。

### 1.3. 从高费率子集到全线性化
上面提到的算法有一些多余的细节。每一步，它对每个chunk维护一个自由$t_i$，但其实一个chunk中哪个$t_i$作为自由变量是无所谓的，并且整个图中哪个$t_i>0$也是很自然可以得到的，因为每一步中都会有一个费率最高的chunk，那个chunk的任何一个$t_i$都可以作为$t_i>0$。所以我们可以对上述算法做一些简化：
- 去除对$t_i$变量的追踪。每一步的包含chunk就是当前费率最高的chunk，其余chunk都是被排除
- 不和上一步的包含chunk的费率进行比较：
    - 在决定将哪个$d_j$变为基变量时，不要把top chunk或者bottom chunk去和当前的包含chunk的费率进行比较，而是只要top chunk的费率大于bottom chunk就可以进行分割。
    - 在决定将哪个$d_j$变成自由变量时，只要满足bottom chunk的费率高于top chunk的费率即可。
    - 以上做法实际上导致每一步不仅仅是优化包含chunk（即最高费率拓扑有效子集），而是同时优化所有chunk。当算法结束的时候，不仅最高费率拓扑有效子集被找到了，次高，次次高费率拓扑有效子集也被找到了，他们依照费率从高到底排列着，Cluster的线性化已经完成了。$^7$

由此，总体而言，我们找到了一种算法，它的状态是一个生成森林（每个chunk是一个生成树，整个cluster是一个生成森林），它的目标是找到整体的线性排列而不是最优的那个chunk。

## 译者注
$[1]$ 其实笔者认为按照单纯形法的原理，目标函数的$g$不应该被视为变量，所以这里是$n+m$个变量和$m+1$个等式。每次选取$n-1$个变量作为自由变量，$m+1$个变量通过$m+1$个等式解出。这样理解更顺畅。

$[2]$ 在本文中笔者还是选择使用$chunk$而不是中文，这样可以使表达更清晰。

$[3]$ 如果想不明白可以阅读单纯形法介绍文章。

$[4]$ 假设有$k$个chunk。则组成所有这些chunk的边（自由$d_j$）总共有$n-k$个，可知自由$t_i$总共有$(n-1)-(n-k)=k-1$个，一个chunk最多有一个自由$t_i$，所以$k$个chunk中正好有$k-1$个chunk各自正好包含一个$t_i$，剩下一个chunk正好包含一个基$t_i$。从寻找最高费率拓扑有序交易集合的实际意义层面去理解，就是有且仅有一个chunk被选中作为结果集合（最高费率拓扑有序交易集合）。

$[5]$ 包含指的是作为结果集合，即chunk中有一个$t_i>0$。排除指的是不作为结果集合，即chunk中有一个$t_i=0$。

$[6]$ 每一步必然有且仅有一个$t_i>0$，如果我们把上一步的非零$t_i$变成了0，那么就要选择另外一个$t_i$，这个新的$t_i$只能是①或②中的新chunk，因为这个chunk比原来的结果集的费率高。但如果这个新chunk依赖于其他chunk，那么就不能作为结果了。

$[7]$ 读到这里你应该已经明白，当前的算法已经不是单纯形法了，而是借鉴了单纯形法的思想，每一步做的事情不再是单纯形的单步换基，而是多次换基，且这多次换基并非都是为了优化“寻找最高费率拓扑有序子集”问题的目标函数$g$，而是同时优化“所有费率拓扑有序子集”。更通俗的来讲，原来的单纯形法的每一步都是优化最高费率chunk，直接无法优化时单纯形法结束，然后我们把最优chunk剔除，对剩余的chunk再次做单纯形法，知道所有chunk都被找到。而现在则是每一步同时优化所有chunk，算法结束时所有chunk都处于最优状态了。
